This repository contains the code for  [[https://blog.rtshkmr.com/posts/series/songs_of_the_ocaml_compiler/?utm_source=repo&utm_medium=repo_hosting&utm_campaign=songs_of_the_ocaml_compiler&utm_term=didactic_repo&utm_content=blog_series_section_in_readme][Songs of the OCaml Compiler]]  — a blog series on learning OCaml by building something real.

It's a deterministic, replayable simulator of *single-decree Paxos* under node crashes and network partitions, written in OCaml. Set in the Sahara Desert: five caravans — /Aghilas, Taziri, Amastan, Itri, and Tassadit/ — must agree on a campsite despite sandstorms, collapsed messengers, and uncertain paths across the dunes.

The simulation engine is deliberately hand-rolled --- no networking layer, no async runtime --- which keeps every subsystem legible and opens a natural path for future iterations to incrementally introduce real dependencies, turning the simulator into something closer to a usable Paxos-adjacent toolkit.

The codebase builds on Jane Street's OCaml stack (=Base=, =Core=, =ppx_jane=), following the idioms from /[[https://dev.realworldocaml.org/][Real World OCaml]]/ --- the /primary learning substrate/ I used for this project (my maiden line of code written in OCaml was in this repo).

Run =make magic -log_level=debug= to see the protocol in detail.
Custom scenarios can be scripted via JSON.

* Quickstart

Please see the [[file:Makefile][Makefile]] and read the runner scripts before diving in --- it's a good habit.

*Assuming a unix-based machine* (Linux, macOS, BSD...):

** OCaml folks

Just run =make magic=.

** First time setup

For folks trying OCaml for the first time, there are 3 steps:

1. Run =make setup=

   This *setup script is for convenience* and follows the instructions [[https://ocaml.org/install#linux_mac_bsd][from the official docs (follow instructions if setup script doesn't play nice)]]:
   * Installs [[https://opam.ocaml.org/][opam]] (the package manager)
   * Creates a local OCaml switch in =paxos/_opam=
   * Installs OCaml and dune via opam
   * Installs all locked project dependencies

2. Update your =PATH= variable and reload your shell.

   Follow the instructions that =make setup= provides at the end of its run. Common sources of error:

   * Remember to reload the shell (restart your terminal, or source your config: =source ~/.zshrc=).
   * You'll need =opam= and =dune= accessible from your shell. Calling =which opam= should point to where opam was placed.
   * =which dune= and =which ocaml= should resolve to locations within the local opam switch.

3. Run =make magic=!

   It will:
   - check =opam= / =dune= are accessible
   - activate the local opam switch
   - build the project incrementally
   - run the simulator with any flags you supply

Once it's running, type =/help= into the prompt (=>>>=) to see what's available.

* What This Is

Distributed systems are invisible. Consensus protocols --- the rules that let a cluster of nodes agree on something despite failures --- are especially hard to build intuition for by reading papers or tracing production code alone.

This simulator makes causality, message ordering, and failure modes /observable/: you can step through time, watch quorums form and collapse, and see exactly why certain invariants hold even when the desert turns hostile.

#+begin_quote
The five caravans must agree on which campsite to head to. A messenger from Tassadit collapses early. A sandstorm splits the group into two partitions that cannot reach each other. A first proposal from Aghilas fails to gather quorum. The storm clears, the messenger recovers, and a fresh proposal from Itri runs the full Paxos protocol to completion.
#+end_quote

The hand-rolled design is intentional: because there is no framework absorbing the interesting decisions, every subsystem --- the event bus, the logical-time engine, the role state machine --- is a legible teaching surface. Future iterations can introduce real networking, persistence, or multi-decree extensions incrementally, and each step will have something to show for itself.

** Scope of v0 (tag =v0-simple-paxos=)

| To keep the safety argument small enough to trace by hand, v0 leaves some things out on purpose:                  |
|-------------------------------------------------------------------------------------------------------------------|
| *One decision*, not a replicated log.                                                                               |
| *No leader and no failure detection.* Any node may propose, and there are no timeouts.                              |
| *Crash-recovery without reconciliation.* A recovering node keeps its state, but nothing brings laggards up to date. |
| *Modelled concurrency.* Concurrency is an interleaving of events on a single-threaded loop.                         |

* Invariants Asserted

The tests live in [[file:paxos/test/][paxos/test/]] in three suites:

| Suite          | Level                                 | Covers                                                 |
|----------------+---------------------------------------+--------------------------------------------------------|
| [[file:paxos/test/test_quorum.ml][test_quorum.ml]] | pure functions, no simulator          | quorum arithmetic, proposal ordering, value adoption   |
| [[file:paxos/test/test_fsm.ml][test_fsm.ml]]    | role state machines, no simulator     | legal transitions, role isolation, every runtime guard |
| [[file:paxos/test/test_e2e.ml][test_e2e.ml]]    | headless simulator, full message loop | fault scenarios run to completion                      |


Run the tests with =make test=.

** Protocol Properties Tested

| Property                                                                                                                                                                                                                                                                                                                                           | How it's checked                                                                                                                                                                       |
|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| *Agreement*: every node that learns a value learns the same one.                                                                                                                                                                                                                                                                                     | Via e2e, in each scenario that reaches a decision: a healthy cluster, a 2+1 partition, and a crash followed by recovery under a new proposer.                                          |
| *Validity*: the value learned is the value that was proposed, pinned exactly in the same three scenarios.                                                                                                                                                                                                                                            | In the recovery scenario, the first proposal never reached quorum, and the cluster learns the second proposer's value.                                                                 |
| *No decision without a majority*: with 2 of 3 nodes crashed, nothing is decided.                                                                                                                                                                                                                                                                     | In a partition, the minority node stays pending while the majority side decides.                                                                                                       |
| *Quorum threshold*: a quorum is ⌊n/2⌋+1 in both phases (majority quorum rule).                                                                                                                                                                                                                                                                       | Checked for n = 3 and n = 5, and a majority of nacks ends the round.                                                                                                                   |
| *Promise ordering*: an acceptor grants phase 1 only to proposal ids ≥ its current promise, and accepts in phase 2 under the same rule.                                                                                                                                                                                                               | Proposal ids are totally ordered over =(seq, node_id)=. The tests cover the node-id tiebreak and the exact boundary (one below the promise is rejected, the promise itself is accepted). |
| *Value adoption*: once phase 1 reaches quorum, the proposer must carry forward the value of the highest-numbered prior acceptance it hears about. It may use its own value only if no acceptor reports one. The choice does not depend on the order in which promises arrive. This rule is what stops a later round from choosing a different value. | Tested with competing prior acceptances, at the unit level only.                                                                                                                       |


** State-machine Properties Tested
- Writing one role's sub-state through the =role_selector= GADT leaves the other two roles untouched.
- Every runtime guard in the state-machine layer has a test proving that it fires on illegal input: =is_quorum_reached= on an =Idle=, =Preparing=, =Decided= or =ProposerInactive= proposer, and the promise accessors on an =AcceptorInactive= acceptor. These guards are the known debt discussed in [[https://blog.rtshkmr.com/posts/series/songs_of_the_ocaml_compiler/ii/?utm_source=repo&utm_medium=repo_hosting&utm_campaign=songs_of_the_ocaml_compiler&utm_term=didactic_repo&utm_content=blog_series_section_in_readme#fsm_invariants][Part II]]. The header of =test_fsm.ml= lists them.
- A node that is deactivated and reactivated still keeps what it has learned.

**  Pending Testing Objectives
- *At most one value chosen, across competing proposers.* No end-to-end scenario has two proposers racing. This guarantee is tested only through its mechanism (value adoption and promise ordering) at the unit level.
- The scenarios are fixed and hand-written, all on 3-node clusters. There is no randomised or property-based exploration of event orderings yet.
- The guards in =node.ml= (=propose=, =announce_decision=, and the dispatch catch-alls) run inside the end-to-end tests, but no test checks directly that they fire.
